# מיני פרויקט: MediaShelf — מעקב מדיה אישי עם טיפוסים

**טכנולוגיות:** React + TypeScript (קומפוננטות פונקציונליות בלבד)

## סקירה כללית

אתם בונים את **MediaShelf** — אפליקציה קטנה למעקב אחרי ספרים וסרטים שאתם רוצים לקרוא/לצפות. באפליקציה יש שני טאבים (ספרים / סרטים), וכל אחד מהם מסתמך על אותו רכיב רשימה גנרי הניתן לשימוש חוזר. הנתונים נשמרים ב-`localStorage`, כך שהם נשארים גם אחרי רענון הדף.

הפרויקט בנוי כך שלכל קונספט נדרש ב-React יש סיבה טבעית להופיע באפליקציה — שום דבר לא נדחס בכוח רק כדי לסמן וי.

## מטרות למידה

בסיום, הקוד שלכם צריך להדגים:

- [ ] **קומפוננטות** — פיצול לקומפוננטות פונקציונליות קטנות עם אחריות אחת
- [ ] **Props** — מוקלדים עם `interface`, בלי `any` מרומז
- [ ] **useState** — state מוקלד עבור הפריטים, שדות הטופס, הטאב הפעיל וטקסט החיפוש
- [ ] **useEffect** — סנכרון ה-state עם `localStorage`, וגם אפקט אחד לפחות עם פונקציית ניקוי (cleanup)
- [ ] **useRef** — ref על ה-DOM (למשל מיקוד אוטומטי על שדה קלט) **וגם** ref שאינו על ה-DOM (למשל שמירת ערך קודם או מזהה טיימר)
- [ ] **Generics** — קומפוננטה גנרית אחת לפחות, שמשמשת עבור שני סוגי נתונים שונים
- [ ] **רשימות** — רינדור מערכים עם `.map()` ועם `key` יציב וייחודי
- [ ] **רינדור מותנה** — מצב טעינה, מצב ריק, מצב "אין תוצאות חיפוש"

## התקנה

```bash
npm create vite@latest mediashelf -- --template react-ts
cd mediashelf
npm install
npm run dev
```

שמרו על `strict: true` בקובץ `tsconfig.json`. אל תשתמשו ב-`any` בשום מקום — אם יש לכם פיתוי לעשות זאת, כנראה חסר לכם טיפוס או generic.

## מודל הנתונים

התחילו עם שני הטיפוסים הבאים:

```ts
interface Book {
  id: string;
  title: string;
  author: string;
  pages: number;
  finished: boolean;
}

interface Movie {
  id: string;
  title: string;
  director: string;
  durationMinutes: number;
  finished: boolean;
}
```

שימו לב ש-`Book` ו-`Movie` לא חולקים interface משותף בכוונה — זה מה שהופך את רכיב הרשימה הגנרי להחלטת עיצוב אמיתית, ולא לפורמליות.

## שלבים

עברו על השלבים הבאים פחות או יותר לפי הסדר.

### שלב 1 — שלד סטטי
*קונספטים: קומפוננטות, props, רינדור מותנה*

בנו את הלייאאוט בלי state בכלל — קבעו כמה ספרים/סרטים לדוגמה כקבועים.

- `App` מרנדר קומפוננטת `Tabs` ואת הרשימה הפעילה
- `Tabs` מקבלת `active: 'books' | 'movies'` ו-`onChange` בתור **props** ומרנדרת שני כפתורים
- רינדור מותנה של תצוגת הספרים או תצוגת הסרטים בהתאם ל-`active`

### שלב 2 — State והוספת פריטים
*קונספטים: useState, רשימות*

- `useState` עבור מערך הספרים, מערך הסרטים, והטאב הפעיל
- קומפוננטת `AddItemForm` (עם props מוקלדים ל-`onSubmit`) שמאפשרת למשתמש להוסיף ספר או סרט חדש
- רנדרו כל רשימה עם `.map()` — השתמשו ב-`id` בתור ה-`key`, לעולם לא באינדקס של המערך
- לחיצה על צ'קבוקס "הושלם" מחליפה את הערך הבוליאני `finished` של הפריט (תרגלו עדכון מערך ב-state בצורה immutable)

### שלב 3 — שמירת מצב עם useEffect
*קונספטים: useState, useEffect*

- אתחלו את ה-state של `books` ו-`movies` מתוך `localStorage` עם lazy initializer, למשל `useState<Book[]>(() => JSON.parse(localStorage.getItem('books') ?? '[]'))`
- הוסיפו `useEffect` עבור `books` שכותב ל-`localStorage` בכל שינוי במערך, ועוד אחד נפרד עבור `movies`
- ודאו שזה עובד על ידי רענון הדף — הפריטים שלכם אמורים להישאר

### שלב 4 — Refs
*קונספטים: useRef*

- הוסיפו שדה חיפוש שמסנן את הרשימה הנוכחית לפי כותרת. השתמשו ב-`useRef<HTMLInputElement>(null)` כדי למקד אותו אוטומטית בכל מעבר בין טאבים (דרך `useEffect` שתלוי בטאב הפעיל)
- הוסיפו אינדיקציה קטנה של "נוסף לאחרונה": השתמשו ב-`useRef` שאינו על ה-DOM כדי לזכור את הכותרת של הפריט האחרון שנוסף בלי לגרום ל-re-render, והציגו את זה כ-"נוסף לאחרונה: X"

### שלב 5 — קומפוננטת רשימה גנרית
*קונספטים: generics, props, רשימות*

החליפו את שני בלוקי הרינדור הנפרדים ברכיב אחד לשימוש חוזר:

```tsx
interface GenericListProps<T> {
  items: T[];
  getKey: (item: T) => string;
  renderItem: (item: T) => React.ReactNode;
  emptyMessage: string;
}

function GenericList<T>({ items, getKey, renderItem, emptyMessage }: GenericListProps<T>) {
  // רינדור מותנה: מצב ריק מול רשימה ממופה
}
```

השתמשו ב-`<GenericList<Book> ... />` וב-`<GenericList<Movie> ... />` עם פונקציות `renderItem` שונות.

### שלב 6 — ליטוש ומקרי קצה
*קונספטים: רינדור מותנה, ניקוי ב-useEffect*

- דמו מצב "טעינה" ראשוני בעליית האפליקציה (`useEffect` עם `setTimeout`, **עם פונקציית ניקוי תקינה** שמנקה את הטיימר ב-unmount) — הציגו הודעת טעינה עד שהמצב מסתיים
- טפלו במקרה שבו "טקסט החיפוש לא מתאים לכלום" עם הודעה נפרדת משלו, שונה מ"הרשימה ריקה"
- הציגו מספר פשוט בכל טאב, למשל "ספרים (4)"

## בונוס (אופציונלי, רק אם יש זמן)

## מוקשים נפוצים לשים לב אליהם

- שימוש באינדקס של המערך בתור `key` — נשבר ברגע שאפשר למחוק או לסדר מחדש פריטים
- לשכוח שעדכוני `useState` הם אסינכרוניים — קריאת state ישן מיד אחרי קריאה ל-setter
- שינוי (mutation) ישיר של המערך/אובייקט ב-state במקום יצירת אחד חדש
- קומפוננטה גנרית רק בשם — אם היא תמיד נקראת עם טיפוס קונקרטי אחד בלבד, שווה לשאול אם היא בכלל הייתה צריכה להיות גנרית
